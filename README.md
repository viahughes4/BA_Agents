# OTT Technical Business Analyst Agent

A [Claude Code](https://docs.anthropic.com/en/docs/claude-code/quickstart) agent for Project Managers delivering whitelabel OTT (Over-The-Top) streaming products. Built around Accedo Broadband's professional-services delivery patterns.

The agent operates as a senior Technical Business Analyst with deep OTT domain knowledge — DRM systems, player SDKs, platform certifications, D-pad focus management, multilingual edge cases, ad insertion architectures — and applies that knowledge proactively to scope, story, and validate work.

It is opinionated by design. It surfaces ambiguity rather than guessing, refuses to write to Jira or Confluence without explicit approval, and pushes back on requests that skip steps.

**Optimised for AI-assisted code generation.** Story specifications are written so AI codegen tools can build correctly from them and human QA can verify the result without re-discovering scope. Validation is built into generation — `/generate-stories` self-validates and emits an Issues appendix only when checks fail, so you don't run a separate review pass on clean output.

**Loose Agile.** Sprint-points-velocity ceremony is optional, not default. The agent works equally well on continuous-delivery, milestone-driven, or sprint-based engagements. Story sizing is tiered (Minimal / Standard / Heavy) by complexity, not by sprint capacity.

## What it does

13 PM-facing slash commands available once Claude Code launches in this directory:

| Command | Purpose |
|---|---|
| `/onboard-project` | Conversational PM intake; populates per-engagement project context |
| `/sow-importer` | Parse a client SOW or PRD and bootstrap `project-context.md` |
| `/gap-analysis` | Score a doc against the whitelabel catalog **and** AI-codegen spec readiness |
| `/feature-discovery` | Pre-story analysis (Light mode for trivial features, Full 15-dimension report otherwise) |
| `/generate-stories` | Tiered Jira-ready stories (Minimal / Standard / Heavy) with self-validation |
| `/generate-prd` | Opt-in PRD assembly — only run when client contract requires the artefact |
| `/validate-stories` | 5-lens validation in `full` mode, or `fast` mode (AI-Buildability + AC quality) for re-checks |
| `/validate-ac` | Single-story AC check; alias for `/validate-stories fast` |
| `/jira-cleanup` | Spec-readiness, decision-blocked, and traceability checks with PM-gated remediation |
| `/cert-checklist` | Per-platform certification readiness scan |
| `/estimate-review` | Compare estimates against catalog typical-effort ranges (sprint-only signals are optional) |
| `/status-report` | Delivery Snapshot / Sprint Report / Weekly / Executive / Release Readiness |
| `/meeting-helper` | Prioritised PM digest from meeting transcripts |

Six sub-agents handle the underlying machinery and are invokable directly:

| Command | Purpose |
|---|---|
| `/sub:context-loader` | Validate `project-context.md` and return a context block |
| `/sub:catalog-match` | Match input fragments against the catalog with calibrated confidence (High / Medium / Low / None); coverage checks for gap analysis |
| `/sub:jira-read` | Read-only Jira retrieval (issue, JQL, sprint, epic, decision-blocked, stale) |
| `/sub:jira-write` | Jira writes with mandatory PM approval gate |
| `/sub:confluence-read` | Confluence search, page reads, comments |
| `/sub:confluence-write` | Confluence create / update with PM approval gate |

## Quick start

### Prerequisites

- [Claude Code](https://docs.anthropic.com/en/docs/claude-code/quickstart) installed
- (Optional) Atlassian MCP connected via your Claude.ai integrations — required for Jira / Confluence skills to write directly. Without it, the sub-agents gracefully degrade and ask you to paste data.
- (Optional) Slack MCP — already wired up in `.mcp.json`

### Run it

```bash
git clone <repo-url>
cd tba-agent
claude
```

CLAUDE.md, the catalog, and all slash commands load automatically. Your first command on a new engagement is almost always:

```
/sow-importer        # if you have a SOW or PRD doc
/onboard-project     # if you don't, or to fill in gaps after sow-importer
```

Both produce `project-context.md` — the per-engagement file every other skill consults.

## Architecture: two-file pattern

The agent uses a deliberate split between **what's possible** and **what's chosen**:

| File | Role | Lifecycle |
|---|---|---|
| `OTT-requirements-reference.md` | **Catalog** of every feature, system, and requirement deliverable on a whitelabel OTT engagement, with possible values for each | Static. Updated only when the offering itself changes. Like `.env.example`. |
| `project-context.md` | **Per-engagement** values — the actual selections for the current project | Generated by `/onboard-project` or `/sow-importer`. **Gitignored — local only.** Each PM maintains their own copy for their active engagement. Like `.env`. |

The catalog is the menu. The project-context file is the order. Skills consult both:

- **Catalog** → option lookups, gap analysis baseline, cert requirements, effort benchmarks
- **Project-context** → platform scope, DRM provider, Jira key, language list, delivery cadence

When `project-context.md` is absent or partial, PM-facing skills proceed with `⚑ Open` blocks for every missing field and recommend running `/onboard-project` once at the top of the output.

## Recommended workflow

The default cycle is documented in `CLAUDE.md → TYPICAL WORKFLOW` — not every skill runs on every feature.

```
Setup
├── /sow-importer        → bootstrap project-context.md from a real client doc
├── /onboard-project     → fill any gaps the SOW didn't cover
└── /gap-analysis        → score the SOW against the catalog and for AI-codegen spec readiness
                           (resolve every ⚑ before feature work)

Cert prep
└── /cert-checklist      → lock platform cert obligations early

Per feature
├── /feature-discovery   → only for non-trivial features (multi-platform, system boundary,
│                          playback / auth / payment, multi-locale UI). Trivial features
│                          skip directly to /generate-stories.
└── /generate-stories    → tiered output, self-validates, emits an Issues appendix
                           only if any AI-Buildability check fails.

Periodic
├── /jira-cleanup        → spec-readiness, decision-blocked, traceability checks
└── /status-report       → Delivery Snapshot internally; client-facing variants
                          for stakeholders

On demand only
├── /validate-stories    → re-check stories that came from outside this agent
│                          or were heavily edited
├── /validate-ac         → single-story AC check (alias for /validate-stories fast)
├── /estimate-review     → only when sprint-based delivery + estimates are tracked
├── /generate-prd        → only when client contract requires a PRD artefact
└── /meeting-helper      → digest from meeting transcripts
```

### Five rules for getting maximum value

1. **Always start with `/sow-importer` or `/onboard-project`.** Skills run against vague context produce vague output.
2. **Treat every `⚑ DECISION REQUIRED` as a real action item.** Surfacing ambiguity is a feature, not noise. Under AI codegen, unresolved decisions become wrong code in hours.
3. **Run `/feature-discovery` for non-trivial features only.** Light mode kicks in automatically for trivial scope; Full mode runs the 15-dimension analysis when warranted.
4. **Trust `/generate-stories` self-validation.** Re-running `/validate-stories` on its output is duplicate work. Use `/validate-stories` only when stories came from elsewhere or were heavily edited.
5. **Run `/cert-checklist` 4–6 weeks before submission**, not 2 days before. Cert windows are slow.

## Behavioural guarantees

The agent enforces these rules, defined in `CLAUDE.md`:

- **Uncertainty flagging** — never silently assumes. Two forms: a Short one-liner (`⚑ Open: <one-liner> — defaulting to <X> unless changed`) for low-stakes choices, and a Full `⚑ DECISION REQUIRED` block for material decisions affecting scope, cost, cert, or architecture.
- **Project context first** — every PM-facing skill validates `project-context.md` before running. Missing or partial context raises `⚑ Open` blocks inline rather than blocking; `project-context.md` is gitignored and managed locally per PM.
- **Clarification before generation** — up to 3 targeted questions when scope, user need, design reference, or integration contracts are missing.
- **Human approval gate** — `_jira-write` and `_confluence-write` never execute without explicit PM `confirm`.
- **Localization awareness** — automatically includes l10n / i18n in acceptance criteria for any UI story on a multilingual project.
- **Output style** — concise language, omit-empty sections, differences over completeness, no preamble. Applied to every skill globally via `CLAUDE.md → OUTPUT STYLE`.

## Customising for other delivery shops or domains

This agent is tuned for Accedo Broadband's whitelabel OTT offering. To adapt:

- **Catalog** — `OTT-requirements-reference.md` is your inventory. Edit systems, features, and effort ranges to match your offering.
- **Platform reference** — the table in `CLAUDE.md` lists supported platforms, frameworks, DRM, cert authorities. Add or remove rows.
- **Behavioural rules** — domain-agnostic; portable to any delivery shop.
- **Skills** — each is a self-contained markdown file in `.claude/commands/`. Modify, add, or remove freely; skills compose by referencing each other as slash commands.

---

## Limitations

This agent is **not**:

- An autonomous Jira / Confluence editor — every write requires explicit PM approval.
- A replacement for technical architects on novel system design.
- Calibrated for non-OTT product domains — platform / DRM / cert knowledge won't apply outside streaming.

It produces specifications optimised for AI-codegen consumption (concrete inputs/outputs, integration contracts referenced, no vague verbs in ACs) and human verification — but it does not invoke AI codegen tools itself. The output is the spec; the build still happens in your codebase pipeline.

## Versioning

- **Agent version** is set in `CLAUDE.md` header (currently 2.2).
- **Catalog version** is the `Last imported` date in `OTT-requirements-reference.md`.
- **PRD version** is set by `/generate-prd` (0.1 on create, minor bumps on update, PM promotes to 1.0 on approval).
